# Meet

Meet 是一个私有部署、供家庭内部使用的 AI 实时语音角色扮演 Web 应用。

用户可以和具有稳定人设、自然声音与长期记忆的 AI 角色实时交谈，例如：

- 孩子与英雄角色聊天；
- 向数学老师请教问题；
- 成年人与影视风格角色谈心；
- 创建自己的陪伴、教学或娱乐角色。

## 当前状态

项目已经完成需求基线、技术栈选择并进入 MVP 业务开发阶段。当前代码可以启动 React PWA、Fastify API 和独立 `pg-boss` Worker，并通过带账号认证的 Fastify WebSocket 中继连接 `qwen-audio-3.0-realtime-plus`、`qwen-audio-3.0-realtime-flash` 或豆包实时语音 3.0 全双工版本；浏览器发送 16 kHz PCM，使用可清空的 24 kHz PCM 播放队列。千问仍是三个预置角色和第一版的默认 Provider，豆包作为显式可选的中文角色表现对照组，不在故障时静默切换。WebRTC 链路保留为实验与诊断路径。账号、家庭成员、三个预置角色、结构化角色卡、角色权限、角色首页、实时通话、会话/消息持久化、私人历史、最近历史续聊、约 30 秒断线恢复，以及会话摘要、分级长期记忆和记忆审阅页面已经实现；当前账号与指定角色的文字历史、摘要和长期记忆也可以导出并合并到另一个账号继续关系。成人配置、儿童使用的“学习小支线”首个受控纵向切片也已接入千问 WebSocket 产品通话：儿童先看到透明说明，可以选择只聊天或主动开始一次微挑战，符合严格门槛时也可由角色轻轻邀请；每次通话最多一次、最多两次角色回复。MediaStore、本地私有对象目录、媒体元数据、受权读取/保留/删除和 `media.expire` 幂等清理基础也已完成；按次录音采集与历史回放仍待接入。

已经确认的方向：

- 私有部署、家庭内部使用，不开放公众注册；
- 支持多个家庭成员独立登录，各自的对话历史和记忆相互隔离；
- 账号分为管理员、成人和儿童；儿童使用与成人相同的界面，仅按权限隐藏不能执行的操作；
- 家庭成员只能由管理员创建，所有账号统一使用用户名和密码；
- 每台设备只保持一个登录账号，切换成员时需要先退出再登录；
- 管理员可以重置成员密码；管理员密码通过服务器命令重置；
- 儿童账号的历史可见范围按账号配置，默认管理员可查看；成人账号的私人内容对管理员不可见；
- 主要在中国大陆使用，服务部署在国内云服务器；
- 具体云平台、域名、HTTPS、快照和生产运维由项目所有者自行处理，不纳入应用产品范围；
- 手机和平板优先，桌面浏览器兼容；
- 支持安装为全屏 PWA，但实时聊天仍需联网；
- 应用不设置全局并发通话上限，容量由部署环境和模型供应商额度决定；
- 第一版不提供推送、定时提醒或角色主动来电；
- PWA 进入后台时尽力保持通话，被系统暂停后在回到前台时自动恢复；
- 网络中断后自动重连最多约 30 秒，并恢复上下文与已完成记录；
- 模型故障只重试当前模型，持续失败时暂停通话，不静默更换模型或声音；
- 推理和语音主要使用云端模型；
- 前后端统一使用 TypeScript；
- 数据使用 PostgreSQL，媒体文件放在独立文件目录或对象存储；
- 代码采用 Monorepo，至少拆分 Web、API 和共享协议包，并按需增加后台任务进程；
- Web 使用 React、Vite 和 `vite-plugin-pwa`；
- API 使用 Fastify，必要的服务端长连接使用 `@fastify/websocket`；
- PostgreSQL 访问与迁移使用 Drizzle ORM，同时允许复杂查询直接写 SQL；
- Monorepo 使用 pnpm workspace；
- Web/API 共享协议使用 Zod 做运行时校验；
- 后台任务使用 `pg-boss` 和现有 PostgreSQL，不引入 Redis；
- 媒体通过统一 MediaStore 访问，默认本地目录，也支持 S3 兼容对象存储；
- 第一版优先自然、低延迟、有角色感的实时语音聊天；
- 第一版是通用角色平台，预置儿童英雄、数学老师和成人情绪陪伴三类角色；
- 三个预置角色首次部署后即可通话，管理员可以复制修改，并可恢复原始版本；
- 支持用自然语言让 AI 快速生成角色，并通过结构化角色卡或完整 Prompt 高级模式继续编辑；
- 第一版使用静态头像和轻量状态动画，不做 Live2D 或数字人口型；
- 角色头像支持内置图片、用户上传和根据角色卡 AI 生成；
- 角色卡可以导入导出，但不包含私人对话、记忆或录音；
- 当前账号可以按角色导出私人文字历史、摘要和长期记忆，并在另一个账号的对应角色中幂等导入；
- 预置及管理员创建的角色全家共享，个人角色默认私有并可主动共享；
- 儿童只能使用家庭公共角色，不能创建角色；
- 私人记忆保持隔离，同时可以维护一份明确的家庭资料；
- 家庭资料仅管理员可以编辑，成人和儿童只能在角色对话中读取使用；
- 与同一角色默认延续关系和记忆，也可以发起不写入长期记忆的临时对话；
- 明确事实可自动进入私人记忆，存疑内容需要用户确认；
- 原始通话录音默认不长期保存，可以按次开启或在结束时选择保留；
- 通话页采用自适应形态：默认沉浸式，教学等角色可以展开字幕和辅助内容；
- 首页以角色卡为主，突出最近通话和收藏；所有账号的角色卡都使用独立通话按钮；
- 手机使用角色、历史、记忆、我的底部导航，桌面自适应为侧边栏；
- 通话默认免提并使用语义轮次与语义打断，嘈杂环境可以切换为按住说话；
- 普通角色只显示当前一句字幕，完整记录可展开；教学角色默认展开字幕和辅助区；
- 角色开场行为可以配置，默认由角色自然打招呼；
- 用户沉默约 10–15 秒后角色可以自然追问一次，之后安静等待；
- 回复长度按角色和语境动态调整，并响应用户“简单点”或“详细点”等要求；
- 通话中支持上传图片或直接拍照；
- 聊天图片默认随历史记录保存，并可以单独删除；
- 数学老师辅助区支持题目图片、Markdown/LaTeX 公式和分步讲解卡片；
- 第一版工具调用只实现计算器，底层保留扩展接口；
- 第一版使用云端预设声音，后续支持克隆音色；
- 每个角色拥有全家一致的固定声音；AI 根据角色卡推荐 3 个预设音色，用户试听后确认；
- 角色卡保存语速、活力、温柔程度和情绪表现等声音风格，通话中可临时调整；
- 视觉采用简洁中性的基础界面，并按角色切换主题色、背景和氛围；
- 通话页使用大幅角色立绘、模糊延展背景、悬浮当前字幕和底部固定控制栏；
- 预置推荐千问 `qwen-audio-3.0-realtime-plus`，部署后由管理员测试、启用并明确设置实时默认；
- Qwen-Audio 不支持图片输入，拍题和教学图片保留 Qwen3.5 Omni Plus Realtime 或独立视觉分析回退；
- 支持豆包实时语音 3.0 全双工版本（Seeduplex，模型 `1.2.6.1`），用于中文角色表现对比测试；
- 从第一天保留模型供应商和音色的可替换边界；
- 应用不实现完整数据备份，部署时依赖云服务器磁盘快照。

## 本地运行

环境要求：Node.js 22.12 或更高版本、pnpm 10。

```bash
cp .env.example .env
pnpm install
pnpm db:migrate
pnpm admin:init --username admin --display-name 家庭管理员
pnpm dev
```

运行迁移前，先在 PostgreSQL 中创建空数据库，并在 `.env` 中填写对应的 `DATABASE_URL`。`admin:init` 只允许在没有任何账号的数据库中执行，密码通过终端遮罩输入两次，不会进入命令历史。Meet 不对密码施加长度或组成强度要求，但不接受空密码。管理员忘记密码时可在服务器执行：

```bash
pnpm admin:reset-password --username admin
```

重置成功后，该管理员现有的全部登录会话都会被撤销。应用不提供公开注册；进入实时语音页面前必须先用已创建的账号登录。

示例配置为了本地 HTTP 开发使用 `AUTH_COOKIE_SECURE=false`；生产环境启用 HTTPS 后必须改为 `AUTH_COOKIE_SECURE=true`。

所有已登录账号都可以从“我的”页验证当前密码后修改自己的密码；修改成功会撤销该账号的其他有效登录会话，当前设备保持登录。管理员还可以从“我的”页进入家庭成员管理，创建成人或儿童账号、重置成员密码，并单独配置管理员能否查看每个儿童账号的历史、记忆和已保留录音。管理员忘记密码时仍需使用上面的服务器命令重置。账号停用与恢复的产品方式仍待确认，本版没有提前实现。

登录后的角色首页会直接显示星盾队长、林老师和知夏三个家庭预置角色。点击角色卡的“通话”按钮会使用该角色已经保存的人设、声音和开场策略进入实时通话，点击卡片其他区域可以查看角色卡。角色人设默认按结构化字段编辑，也可以切换到“完整 Prompt”高级模式直接维护一段完整文本。管理员和成人可以创建、编辑、复制与删除自己的角色；管理员创建的角色默认全家共享，成人创建的角色默认私有并可主动共享，儿童只能查看和使用家庭公共角色。预置角色只能由管理员修改和恢复，恢复不会删除任何成员与该角色的会话或记忆。

角色详情页的“迁移我和这个角色的数据”适用于测试账号转正式账号或更换私有部署：先在来源账号导出 JSON 文件，再登录目标账号、打开对应角色并选择导入。文件包含文字历史、可用于续聊的摘要和长期记忆，不包含账号、密码、模型密钥、角色定义、图片或录音。重复导入同一文件不会重复写入；不同角色之间导入需要再次确认。迁移文件是未加密的私人数据，使用后应放在可信位置或及时删除。完整规则见 [ADR-0036](docs/decisions/0036-account-character-relationship-data-transfer.md)。

角色创建与编辑页只展示管理员已经测试并启用的实时模型和音色。管理员和成人可以为自己有编辑权的角色选择模型与声音并用固定短句试听；儿童没有选模入口。试听由带账号认证的 API 在服务端按角色配置连接供应商，不创建业务会话、不申请麦克风，也不向浏览器暴露 API Key 或 Endpoint。角色形象可以选择内置图片或上传不超过 5 MB 的 JPG、PNG、WebP；上传文件通过私有 MediaStore 保存，并按角色可见性授权读取。

### 学习小支线

这项功能由成人配置、儿童使用，默认关闭。所有未删除的预置角色和家庭公共角色都会显示在配置页，并可以先保存计划；成人私有角色需要先分享给家庭，才能供儿童使用。配置页会区分“可生效”和“待生效”；保存待生效计划不代表当前实时服务已能执行它。

动态教学复用同一套 Qwen Audio Realtime WebSocket 协议和服务端控制器，当前支持 `qwen-audio-3.0-realtime-plus` 与 `qwen-audio-3.0-realtime-flash`。模型名称只是协议兼容门槛，不会自动取得权限：每个实际使用的模型配置 ID/修订和连接 ID/修订都必须逐条加入允许列表；任一修订变化后，新通话都会自动关闭该角色的教学可用性。部署者需要先执行 `pnpm db:migrate`，再在 `.env` 中把 `TEACHING_QWEN_DYNAMIC_ENABLED` 设为 `true`。首条绑定填写在 `TEACHING_QWEN_MODEL_PROFILE_ID`、`TEACHING_QWEN_MODEL_PROFILE_REVISION`、`TEACHING_QWEN_CONNECTION_ID` 和 `TEACHING_QWEN_CONNECTION_REVISION`；如需同时批准 Flash 等第二个配置，再用 `TEACHING_QWEN_DYNAMIC_ADDITIONAL_BINDINGS` 填写完整绑定数组。豆包、Plus/Flash 之外的模型和未批准连接可以保存待生效计划，但不会执行动态支线，也不会静默切换供应商、模型或声音。

直接体验流程：

1. 管理员先在“我的 → 模型设置”创建并测试一个文本模型，启用后绑定“教学计划生成模型（短期计划必需）”用途。没有该用途绑定时不能生成，不会退回本地模板或复用其他用途模型。
2. 管理员或成人从“我的 → 学习小支线”选择儿童、任一预置或家庭公共角色、年级、主题、难度和出现方式。可以填写拼音、乘法、古诗、英语对话、科学或其他任意具体目标，并选择 3～8 个活动和 7 天或 14 天有效期。
3. 点击“生成短期计划”会调用已配置的文本模型，可能产生一次模型费用。网络结果未知时，同一计划修订只查询原任务，刷新页面或更换请求 ID 也不会创建另一份收费任务；如确需再次调用模型，必须先修改并保存学习设置形成新的计划修订。已经成功落库的同修订草稿同样只返回原结果。
4. 生成完成后逐项查看儿童将听到的题目、选项、参考答案、讲解和反馈，再点击“确认并启用”。预览固定标记“模型生成 · 未联网”：当前没有网页、文件或知识库检索，模型内容可能有事实错误，必须由家长核对。候选生成失败或尚未确认时，当前已启用内容保持不变。
5. 待生效角色当前只保留普通聊天，已保存的计划不会发送给未批准的 Provider。Plus 与 Flash 都可以生效，但各自必须用自己的精确配置与连接修订通过能力门禁；批准其中一个不会顺带批准另一个。
6. 对于可生效角色，退出并用对应儿童账号登录，从角色卡进入正常通话。开始麦克风和 Provider 连接前，页面会说明这是 AI、学习目标由家庭成人设置、只记录粗粒度状态且不打分。
7. 儿童选择“知道了，开始聊天”后，可随时点“现在来一个”；选择“合适时轻轻邀请”时，系统还需满足通话至少 5 分钟、至少 6 个有效儿童轮次和 24 小时冷却，才会在安全回复边界尝试一次。
8. 一条支线最多包含一次邀请和儿童回答后的一次简短反馈，随后恢复普通角色指令。儿童点“本次只聊天”或说出明确拒绝/安全优先内容后，本次通话不会再次邀请；临时对话始终只聊天。

模型只返回包含标题、目标摘要和活动的 strict 候选对象；学科、年级、难度、活动数、有效期、schema 与编译器版本由服务端按已保存的计划修订注入，再通过共享协议的 `generated-teaching-plan-v2` strict DTO 和固定运行时编译器。模型可以生成新的活动内容，但不能提供或覆盖这些权威字段，也不能提供系统 Prompt、工具调用或修改“可跳过、不评分、每次通话最多一个活动、最多两次角色回复”等安全规则；成人原始目标和供应商原始响应也不会直接作为实时角色 Prompt。结构校验不能保证全部学科事实正确，因此成人确认不可省略。未来如加入联网或资料检索，将另行保存并展示可核验来源；当前版本不声称已查证。

系统不生成分数、等级、掌握结论或儿童能力画像。第五次真实 Provider Spike 只证明精确目标上的隔离文本动态指令链路，因此这仍是家庭内受控体验，不代表儿童学习效果、长期稳定性或其他设备/Provider 已验证。

通话开始后会创建当前账号自己的会话记录，已确认的用户和角色字幕按稳定 ID 与连续序号幂等保存。第一次实时握手会原子固定角色修订、模型、音色、编译指令和上下文策略；同一通话重连继续使用这份运行时快照，不受后续角色编辑或模型停用影响。长通话每新增约 20 条消息或 12,000 字符转写会异步生成增量摘要检查点；断线恢复时加载最新检查点和其后的原文，避免只保留最近消息而忘记本次通话较早内容。正常结束时会话自动收口；网络或页面异常导致未收口时，历史页会明确标记“未正常结束”。用户选择“延续关系”时，服务端会在角色首次开口前加载同一账号、同一角色的已确认长期记忆、最近会话摘要、当前通话和已完成普通通话中的最近消息，再由版本化上下文装配器按供应商预算优先保留最新内容。其他尚未结束的并发通话不会被注入。“临时对话”仍会保留自己的历史文字、增量检查点并生成本次最终摘要，但不会加载以前的私人关系上下文，也不会提取长期记忆。历史页支持查看完整字幕、再次呼叫同一角色和删除自己的记录。管理员不能读取成人账号的历史；对儿童历史的服务端读取仍受该儿童账号的监护权限配置约束。

正常结束会话时，API 会在完成会话的同一数据库事务中为摘要和记忆分别创建持久工作项；临时会话只创建摘要工作项。有可用用途绑定时，工作项固定记录当时的文本模型配置 ID 后入队；没有绑定时进入“等待模型配置”，不影响会话保存，管理员补齐绑定后自动补发。独立 Worker 按工作项动态解析 OpenAI-compatible Chat Completions JSON Mode 连接，无需重启。只有“明确表达 + 稳定事实 + 高置信度”会自动保存，其他稳定但存疑的内容进入“记忆”页等待处理。最终失败仍保留在死信队列，摘要和记忆结果记录模型配置 ID 与实际模型 ID。

可选的 Mem0 OSS 集成把已确认长期记忆建立为语义索引。它直接运行在 API/Worker 进程内，向量表与业务数据使用同一个 PostgreSQL，不需要 Mem0 云端账号或单独部署 Mem0 服务。PostgreSQL 的 `character_memories` 始终保存权威正文、来源、审阅状态和权限；实时接通时只用当前话题从 Mem0 找到候选本地 ID，再回查权威表校验后注入。同步和删除由 `memory.index.sync` 后台任务完成，失败会重试并在 Worker 重启时补偿；搜索超时或不可用会自动回退到最近记忆。“记忆 → Mem0 诊断”可以对照业务记忆、同步映射与实际 Mem0 记录，查看异常和孤儿记录，并按角色测试真实语义召回。启用前需要 PostgreSQL 提供 pgvector，并在“我的 → 模型设置”中选择内置本地 Embedding 或 OpenAI-compatible 外部服务，测试、启用模型后绑定“长期记忆向量化”用途；具体隐私边界见 [ADR-0032](docs/decisions/0032-mem0-semantic-memory-index.md)。

启用内置 Mem0 时，先在 PostgreSQL 服务器安装与当前数据库版本兼容的 pgvector 扩展文件，再由管理员完成 Embedding 用途绑定。API 与 Worker 会动态读取活动配置，无需重启；首次使用会在当前数据库执行 `CREATE EXTENSION IF NOT EXISTS vector`，并按模式、端点、模型和维度自动派生独立 collection，因此数据库账号需要创建扩展和表的权限。选择“内置本地 Embedding”时，可以从 `fastembed@2.1.0` 支持的 7 个稠密模型中选择；中文家庭场景默认推荐约 90 MB、512 维的 `bge-small-zh-v1.5`，另提供多语言 E5 Large 和 5 个英文模型。首次测试会把所选 ONNX 模型下载到 `EMBEDDING_LOCAL_CACHE_DIR`，之后向量化不发送到外部服务；API 与 Worker 共用模型文件，但各自在内存中加载一份推理实例。配置变化后会自动补发重建任务，旧 collection 需由运维确认迁移完成后清理。

实时 WebSocket 意外断开后，页面会立即关闭麦克风发送并清空旧 PCM，然后在总计约 30 秒的窗口内按 1、2、4、8 秒退避重建同一模型、同一声音的连接。每次重建前先幂等补写尚未确认到服务端的完整字幕；替代会话会加载当前通话和此前关系中已确认的消息，不重放未完成音频，也不会让角色再次说开场白。PWA 返回前台时会检查恢复状态并立即再试，同时重新确认麦克风轨道可用。30 秒仍未恢复时通话进入暂停，用户可以选择“继续重试”或“结束”；结束仍会保存已经确认的记录。临时对话恢复时只加载本次临时通话自己的已确认消息，不会借恢复路径读取其他会话。

### 管理员模型设置

运行 `pnpm db:migrate` 后，管理员从“我的 → 模型设置”按“供应商连接 → 模型 → 音色/维度 → 测试 → 启用 → 默认/用途”的顺序配置。千问和豆包使用各自的实时适配器；文本模型支持 Bearer API Key、HTTPS Base URL 和标准 `/chat/completions` JSON Mode，可选择标准或阿里百炼兼容预设。Embedding 可以选择无 URL、无密钥的内置 FastEmbed 模式，也可以使用 OpenAI-compatible `/embeddings` 外部模式；两者测试时都会校验实际返回维度。连接更新先保存为候选修订，只有真实测试成功才原子替换活动配置。

API 密钥（包括 Embedding 密钥）按已确认方案明文保存在私有 PostgreSQL 中。管理 API 和浏览器永不获得密钥内容，只能看到“已配置”；日志、审计和错误响应也不得包含密钥。数据库或磁盘快照一旦泄露将直接暴露密钥，生产部署必须限制数据库与快照访问。遗留的 `DASHSCOPE_API_KEY`、`QWEN_*`、`DOUBAO_*`、`QWEN_ANALYSIS_*`、`MEM0_ENABLED` 与 `MEM0_EMBEDDING_*` 变量不会被导入或继续读取。

升级保留现有角色、模型和音色 ID，但模型初始为未配置草稿。管理员以相同供应商和模型 ID 新建模型时会重新挂接原记录；完成测试、启用并设置实时默认及两个文本用途后，原角色即可恢复通话，等待分析的会话会自动补发任务。`pnpm dev` 会同时启动 Web、API 和 Worker；也可以分别使用 `pnpm dev:api`、`pnpm dev:web` 与 `pnpm dev:worker`。

媒体对象默认写入 `MEDIA_LOCAL_DIR` 指定的私有目录，数据库只保存不透明对象 key、所有者、类型、大小、校验值和保留状态。生产环境应把该目录放在持久化磁盘，并与 PostgreSQL 一起纳入项目所有者配置的磁盘快照。媒体内容只能通过带账号认证的 API 读取，不使用永久公开 URL。

从角色首页发起通话后，服务端会按角色的 Provider Profile 和 Voice Profile 校验实时模型，浏览器不再向握手接口自由提交模型。然后可以验证：

- 角色先开口与连续免提聊天；
- 实时用户/角色字幕；
- 用户开口时语义打断与手动停止；
- 仍由 `smart_turn` 收尾的本地按住说话备用模式；
- WebSocket PCM 中继、确定性清空旧回复音频和供应商错误事件。

WebRTC 实验路径的设置、协议说明和已知限制见 [千问 WebRTC 技术验证](docs/spikes/qwen-realtime-webrtc.md)；默认传输与打断边界见 [ADR-0026](docs/decisions/0026-qwen-websocket-pcm-playback.md)。

豆包链路仍使用 16 kHz PCM 输入、24 kHz PCM 输出、显式 `response.cancel` 打断和 `session.close` 优雅关闭；模型 ID 由管理员配置并由豆包适配器校验，不再由环境变量固定。详细协议边界见 [ADR-0028](docs/decisions/0028-doubao-full-duplex-realtime-provider.md)，配置生命周期见 [ADR-0029](docs/decisions/0029-admin-managed-model-configuration.md)。

## 下一步

1. 对已接入的千问 Plus/Flash 学习小支线做成人监护下的真实手机/平板产品路径验证，分别记录动态更新、拒绝、恢复、重连、首音延迟和实际费用；在完成安全用例与自然度门槛前，不再扩大模型/Endpoint 绑定或内容目录。专用 Spike 仍只作为隔离协议证据，默认 preflight，真实调用继续要求一次性授权、固定预算和 plan hash 二次确认。第五次 `.10` 的 2 会话/3 响应结果仍为 `insufficient_sample`，不能外推到儿童学习效果、长期稳定性、语音设备或其他 Provider。
2. 在已完成的 MediaStore、媒体元数据和 `media.expire` 清理基础上接入按次录音采集、结束时保留、历史回放与删除；录音封装格式和临时缓冲期限在实现前单独确认。
3. 使用同一组角色脚本在真实手机、平板和桌面浏览器上盲测千问与豆包，记录首音延迟、语义打断、情绪、人设和实际用量，再决定是否调整默认 Provider。
4. 在基础角色闭环稳定后补充 AI 快速创建、头像上传与生成，以及角色卡导入导出。
5. 单独确认管理员停用与恢复家庭账号的产品方式，再实现对应状态流转和会话撤销，不从当前数据库状态字段直接猜测交互。
6. 在业务开发期间并行完成手机与桌面设备实测、延迟和打断记录、图片能力路由，以及 Qwen-Audio Flash 与豆包对照；这些结果用于验收和后续默认模型调整，不再阻塞业务切片。
