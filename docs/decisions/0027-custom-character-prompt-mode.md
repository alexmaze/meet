# ADR-0027：角色卡完整 Prompt 高级编辑模式

- 状态：Accepted
- 日期：2026-08-10
- 修订：ADR-0005 的角色卡编辑与运行时提示词来源

## 背景

结构化角色卡适合普通创建、AI 生成、复用和逐项修改，但熟悉提示词的用户也需要直接控制完整人设文本。强制把已有 Prompt 拆成背景、性格、关系、说话方式、目标和示例台词，会增加编辑成本，也可能改变原始 Prompt 的组织方式。

## 决策

1. 角色人设支持“结构化编辑”和“完整 Prompt”两种定义模式；新角色默认使用结构化编辑。
2. 完整 Prompt 是高级模式。启用后，编辑器隐藏背景、性格、关系、说话方式、情绪风格、对话目标和示例台词等结构化人设输入，只展示一个完整 Prompt 文本框。
3. 完整 Prompt 模式下，自定义文本直接作为角色人设指令主体，运行时不再编译或混入结构化人设栏目。
4. 角色名称、简介、Provider Profile、Voice Profile、头像和视觉配置继续作为独立数据保存。接通后由谁先说、沉默追问和开场白等运行控制也继续保留独立配置；服务端可以把其中需要模型理解的策略追加到自定义 Prompt 之后。
5. 在两种模式间切换时，编辑器保留另一模式已经填写的草稿，避免试用模式或临时切换造成内容丢失；只有当前选中的模式参与运行时人设编译。
6. 既有角色缺少模式字段时按结构化模式读取，不要求迁移已有角色数据。
7. 完整 Prompt 最大 12,000 个字符，经过与其他角色写入相同的权限、长度和运行时总预算校验。Prompt 不得包含或获得供应商密钥等服务端凭据。

## 理由

- 保留结构化默认模式，继续支持低门槛创建、AI 生成、音色推荐和未来角色卡迁移；
- 提供完整 Prompt 模式，让高级用户能原样维护成熟的人设指令；
- 运行配置保持独立，避免 Prompt 文本控制头像、权限、供应商或客户端计时器等非模型行为；
- 兼容性默认值可以让现有数据库中的角色无迁移继续运行。

## 影响

- `PersonaDefinition` 增加可选的定义模式和完整 Prompt 文本；
- 角色编辑器和详情页需要按当前模式显示对应内容；
- 运行时编译器必须保证完整 Prompt 模式不会悄悄拼入结构化人设字段；
- 后续 AI 快速创建、角色卡导入导出和音色推荐需要显式识别两种模式；
- 完整 Prompt 模式降低了结构化可解释性，选择该模式的用户负责文本内部的一致性。
