# ADR-0025：启动业务开发并确定第一版默认实时模型

- 状态：Accepted
- 日期：2026-08-09
- 修订：ADR-0023、ADR-0024 的验证门槛、Provider Adapter 实施顺序与默认模型确定时点

## 背景

`qwen-audio-3.0-realtime-plus` 的浏览器 WebRTC 技术样例已经可运行，代码已覆盖服务端 SDP 代理、`smart_turn`、字幕、语义打断、手动停止和本地按住说话等关键协议路径，其中音轨挂载时序已经过真实链路排障修正。真实手机、桌面设备和家庭噪声环境下的系统化测试，以及与 Qwen-Audio Flash、豆包 S2S-SC 的盲测仍未完成。

项目所有者决定接受当前实时链路作为第一版业务开发基线，不再要求先完成上述真实设备验证和模型对照，才开始账号、角色、会话与记忆等需求开发。

## 决策

1. 立即从实时语音技术样例进入 MVP 业务开发。真实手机、桌面设备和不同噪声环境的验证继续进行，但不再作为业务开发的前置门槛。
2. 第一版默认实时语音实现使用 `qwen-audio-3.0-realtime-plus`，沿用 WebRTC、`smart_turn` 和当前已验证的千问握手时序。默认系统音色仍为 `longanqian`；具体角色通过 Voice Profile 选择并保存声音。
3. 这个选择是第一版的实现默认值，不是对千问、该模型或阿里云的永久绑定，也不表示其他模型已经被否定。
4. Provider Adapter 继续作为强制架构边界。角色卡、会话、记忆、统一实时事件和业务页面不得直接依赖千问事件名、Endpoint、模型参数或专有会话配置。
5. 当前不要求为了形式完整而同时实现多个实时供应商适配器。先完成千问适配器与业务能力的端到端闭环；当实际质量、稳定性、成本、能力缺口或可用性需要时，再接入 Qwen-Audio Flash、豆包或其他供应商。
6. 真实设备验证、延迟与打断指标、长会话稳定性和三类角色体验仍属于 MVP 验收与回归范围。它们可以与业务开发并行，发布验收时仍须记录结果，发现问题后按严重程度修复。
7. 图片与拍题能力仍通过 Provider Capability 路由到支持视觉的模型或独立视觉分析器，不因为默认语音模型不支持图片而删除该需求。

## 理由

- 当前样例已经降低了最关键的协议可行性风险，继续把全部业务开发绑定在更完整的设备矩阵和模型盲测之后，会推迟账号、角色和持久化闭环；
- 先确定一个默认实现可以减少第一版并行适配成本，让开发围绕真实业务流程推进；
- 保留 Provider Adapter 和供应商无关的数据模型，可以把“现在只实现一个供应商”与“永久锁定一个供应商”明确区分；
- 把设备测试保留为并行验收工作，既接受当前模型基线，也不会丢失发布前对移动端、噪声、延迟和稳定性的验证。

## 后果

- 架构实施顺序改为优先建设数据库、认证、角色、会话和记忆等业务纵向切片，不再等待多模型对照完成；
- 千问专有协议继续封装在对应适配器和 SDP 网关内，新增业务代码只依赖统一协议与能力声明；
- 可观测性随业务会话逐步接入，真实设备记录和模型对照可以在可用的完整角色流程上完成；
- 若后续实测暴露不可接受的问题，可以更换默认 Provider Profile 或新增适配器，而不迁移角色内容、私人会话或长期记忆的数据模型；
- ADR-0023 中真实验证先于业务开发和 Provider Adapter 提炼的实施顺序，以及 ADR-0024 中“当前切换只确定验证顺序”和“完成真实设备测试后再决定默认生产模型”的表述，由本决策修订；其模型能力、WebRTC 时序和安全边界继续有效。
