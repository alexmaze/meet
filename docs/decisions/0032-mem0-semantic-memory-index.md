# ADR-0032：以 Mem0 作为长期记忆语义索引

- 状态：Accepted
- 日期：2026-08-13
- 补充：ADR-0006、ADR-0010、ADR-0020、ADR-0030

## 背景

现有长期记忆在 PostgreSQL 中按账号、角色和更新时间读取。它已经支持自动保存、待确认、接受、编辑、拒绝和删除，但实时通话只能一次取回最近的固定数量；记忆增多后，与当前话题相关但较早的事实可能无法进入上下文。直接把全部记忆提交给模型会持续增加 token、延迟和隐私暴露，也无法稳定解决相关性问题。

Mem0 提供记忆写入、更新、删除和带实体过滤的语义搜索。Meet 仍需要保留自己的审阅状态、来源证据、权限与删除语义，不能把这些产品规则委托给向量索引。

## 决策

1. PostgreSQL `character_memories` 继续是长期记忆唯一权威来源；Mem0 只是可重建的语义索引，不直接作为提示词正文来源。
2. 只有 `active` 记忆进入 Mem0。`suggested` 不上传；接受后写入，编辑后更新，拒绝或删除后从索引删除。
3. Mem0 实体边界固定为 `userId = Meet 账号 ID`、`agentId = 角色 ID`，元数据保存本地记忆 ID、内容指纹和来源会话 ID。搜索必须同时过滤账号与角色。
4. 写入使用 `infer: false`，索引的是 Meet 已经审阅分级后的规范化事实，避免 Mem0 再次提取、合并或改变产品侧事实。
5. 新增 `memory_index_entries` 保存本地记忆与 Mem0 ID 的映射、已索引指纹、同步状态、尝试次数和不含正文的错误码。`memory.index.sync` 通过 pg-boss 在业务事务中投递，独立重试和进入死信队列；Worker 启动时补发未同步记录。
6. 实时上下文从当前通话最近的用户消息构造最多 1,600 字符的查询。Mem0 只返回本地记忆 ID和相关度，API 随后重新从 PostgreSQL 校验账号、角色和 `active` 状态，并按命中顺序合并最近记忆。Mem0 返回的正文不直接进入模型。
7. Mem0 搜索超时、不可用、返回非法 ID 或索引尚未追平时，API 回退到 PostgreSQL 最近 `active` 记忆；不能因为语义索引故障阻止实时通话。
8. 临时对话不搜索 Mem0，也不写入长期记忆索引。增量摘要检查点、最终摘要和家庭资料不进入 Mem0。
9. 使用官方 `mem0ai/oss` TypeScript SDK 直接嵌入 API 与 Worker，版本固定为 `3.1.6`。向量存储使用同一 `DATABASE_URL` 的 pgvector，历史记录关闭；不部署独立 Mem0 服务，也不使用 Mem0 Platform API Key。
10. 管理员模型设置提供两种 Embedding 模式：内置模式通过 `fastembed@2.1.0` 在服务端进程内以 CPU/ONNX 加载其支持的 7 个稠密模型之一，固定展示运行时支持的模型 ID、语言和维度，并默认推荐 `fast-bge-small-zh-v1.5`（512 维）；外部模式使用 OpenAI-compatible `/embeddings` 连接。内置适配器按 Mem0 的 `add`、`update`、`search` 动作调用 FastEmbed 的 passage/query 编码；不开放需要服务器文件路径权限的 `custom` 模型入口。模型必须通过真实向量生成并返回预期维度后才能启用；绑定“长期记忆向量化”用途即启用索引。API 与 Worker 按请求或任务动态解析活动绑定，不要求重启。
11. 模式、Base URL（如有）、模型与维度共同派生 collection 名和索引修订指纹；配置变化后使用新 collection 并补发当前有效记忆，避免不同模型或维度混写。旧 collection 不自动删除，由运维确认重建完成后清理。
12. Embedding API Key 沿用模型设置的候选修订、测试后生效、审计和不回显规则，明文保存在私有 PostgreSQL；不得进入浏览器、日志和诊断元数据。官方 SDK 匿名遥测在示例部署中通过 `MEM0_TELEMETRY=false` 关闭。
13. “记忆”页提供按当前账号权限隔离的 Mem0 诊断入口：对照 `character_memories`、`memory_index_entries` 与 Mem0 `getAll` 的实际记录，展示同步状态、外部 ID、索引修订、尝试次数、错误码、正文一致性与孤儿记录，并允许按角色执行真实语义搜索查看分数。诊断可显示当前用户本来有权查看的记忆正文，但不得绕过成人隐私或儿童监护开关，也不得显示向量、密钥、端点或数据库连接信息。

## 隐私与部署边界

- 记忆正文与向量索引都保存在本地 PostgreSQL。内置模式首次测试会从 FastEmbed 的模型源下载约 90 MB ONNX 文件到 `EMBEDDING_LOCAL_CACHE_DIR`，随后记忆正文与召回查询只在 API/Worker 进程内处理；两个进程共用磁盘缓存，但各自加载一份模型。外部模式若 Base URL 指向云端，已确认记忆和召回查询仍会发送给该服务。
- PostgreSQL 服务器必须先安装 pgvector 扩展文件。启用后的 Mem0 OSS SDK 会执行 `CREATE EXTENSION IF NOT EXISTS vector` 并创建 collection 表；数据库账号需要相应权限。Mem0 保持关闭时，普通业务迁移不要求 pgvector 已安装。
- Mem0 的 LLM 推断与 SQLite 历史都被关闭；记忆抽取、审阅、历史和删除语义继续由 Meet 管理。

## 后果

- 记忆上下文从“最近若干条一次性提交”升级为“话题驱动的语义召回 + 最近记忆回退”，提交给实时模型的总预算仍由版本化上下文装配器控制。
- Mem0 可以从 PostgreSQL 重建；索引损坏或丢失不会损失可审阅的产品记忆。
- 搜索增加一次 embedding 调用和本地 pgvector 查询，因此默认超时 1.5 秒并记录 `semantic`、`fallback` 或 `disabled` 诊断，不记录查询与记忆正文。
- 运行时日志仍不记录查询与记忆正文；用户主动打开的 Mem0 诊断页可以在既有记忆读取权限内显示索引正文和测试查询结果，用于排查同步与召回问题。
- 记忆同步与会话摘要、记忆提取任务解耦，向量索引延迟不会改变提取结果或用户审阅状态。

## 重新评估条件

- 需要支持 OpenAI-compatible 之外的 embedding provider；
- 需要支持独立于模型设置的密钥加密或外部密钥管理服务；
- 真实通话数据显示固定阈值、Top-K 或仅使用用户消息构造查询的召回质量不足；
- 需要删除账号、硬删除角色或执行完整的向量索引清除与审计。
