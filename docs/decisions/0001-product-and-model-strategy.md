# ADR-0001：产品与实时模型策略

- 状态：部分由 ADR-0024 修订
- 日期：2026-08-08

说明：第 3、4 项关于第一轮默认模型与低成本对照模型的决定已由 ADR-0024 修订。其余决策继续有效。

## 背景

项目需要支持面向儿童、教学和成人陪伴场景的实时语音角色聊天。项目为私有部署、个人使用，推理主要依靠云端模型。第一版最重要的是自然的角色聊天，而不是尽可能多的功能。

## 决策

1. 第一版采用原生实时语音模型，不采用“独立 ASR → 文本模型 → 独立 TTS”作为主链路。
2. 第一版先使用云端模型预设音色，后续再支持克隆音色。
3. 第一轮技术实现以 `Qwen3.5-Omni-Plus-Realtime` 为默认模型。
4. `Qwen3.5-Omni-Flash-Realtime` 作为低成本模式和对照模型。
5. 使用豆包 `S2S-SC` 做中文角色感和情绪表现的盲测对照；如果实测明显更自然，可以更换默认供应商。
6. OpenAI Realtime 和 Gemini Live 不作为中国大陆部署环境的唯一后端。
7. 角色、声音、会话和记忆的数据模型不得绑定某个供应商。
8. 长期 API 密钥不得下发到浏览器。

## 理由

- 千问同时具备 WebRTC、语义打断、中文和方言能力、预设音色、原生克隆音色路径以及国内节点；
- 千问公开价格较透明，适合个人项目控制成本；
- 豆包 S2S-SC 的明确目标就是强角色和情感陪伴，值得通过实际音频挑战主方案；
- 国际方案能力较强，但官方可用地区和未来自定义音色可获得性会增加个人项目的不确定性；
- 供应商的自然度无法仅靠文档确定，因此最终选择必须依据同脚本盲测。

## 影响

- 第一版的客户端音频层需要兼容 WebRTC，并保留 WebSocket 适配能力；
- 需要建立统一的实时事件、打断和用量记录层；
- 角色提示词与供应商会话配置分开保存；
- 克隆音色阶段优先评估千问或豆包原生能力，效果不满足需求时再评估 ElevenLabs；
- 长会话需要摘要和会话轮换，不能无限依赖供应商上下文。

## 重新评估条件

出现下列情况之一时重新评估：

- 千问在盲测中的自然度、人设稳定性或打断能力明显落后；
- 豆包的个人接入价格或使用限制不可接受；
- 主要部署和使用地区发生变化；
- 某供应商提供了质量显著更高且个人可用的克隆音色实时模型；
- 实际月度成本超过后续确认的预算。
