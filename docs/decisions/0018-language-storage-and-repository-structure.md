# ADR-0018：开发语言、存储与仓库结构

- 状态：Accepted
- 日期：2026-08-08

## 决策

1. Web 和服务端统一使用 TypeScript。
2. 结构化数据使用 PostgreSQL。
3. 图片、头像和录音等媒体放在独立文件目录或对象存储中，数据库只保存元数据与引用。
4. 代码采用 Monorepo。
5. Monorepo 至少区分 Web、API 和共享协议；数据库结构作为共享包管理。
6. 后台任务进程按实际需要增加，第一版不为了形式完整预建空服务。

## 理由

- TypeScript 可以让实时事件、角色结构和 API 数据在前后端共享类型与校验规则；
- PostgreSQL 更适合多账号并发、关系数据、长期记忆和后续检索扩展；
- 媒体与关系数据分开便于存储和清理；
- Monorepo 能保持 Web 与 API 运行边界，同时避免多个仓库的版本同步成本。

## 影响

- 具体 Web 框架、API 框架、数据库访问库和 Monorepo 工具仍需选择；
- 数据库迁移必须进入版本控制；
- 共享协议需要同时提供运行时校验，不能只依靠 TypeScript 编译期类型；
- API 与可选 Worker 需要共享持久任务和幂等规则。
