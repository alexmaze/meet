# ADR-0030：版本化上下文装配与通话运行时快照

- 状态：Accepted
- 日期：2026-08-13
- 补充：ADR-0008、ADR-0024、ADR-0028、ADR-0029

## 背景

实时连接断开后，应用需要用已保存消息创建替代供应商会话。此前上下文直接按字符数裁剪，不同供应商各自拼装；同时每次重连都会重新读取角色与模型配置。这会产生三个问题：角色编辑或模型设置变更可能让同一次通话前后行为不一致；另一条尚未结束的并发通话可能被错误注入；按固定字符预算裁剪容易丢失最新摘要，也缺少可观测的取舍结果。

## 决策

1. 每个业务会话保存且只保存一份 `ConversationRuntimeSnapshot`。快照在第一次通过身份、角色可见性和会话归属校验的实时握手中创建，并通过锁定会话行原子写入；并发握手中最先写入的快照为准。
2. 快照固定角色修订号、实时模型配置 ID、供应商、模型、音色、编译后的角色指令、开场策略和上下文策略版本。API Key、供应商端点及其他凭据不进入快照。
3. 同一业务会话重连时使用已保存快照，不重新采用后来编辑的角色、模型或音色。连接凭据仍按快照中的模型配置 ID 从服务端当前活动修订解析；模型配置随后被停用时，既有会话允许重连，新会话仍按当前启用状态校验。角色可见性与会话归属每次握手都重新校验。
4. 引入供应商无关的 `ContextAssembler`。角色指令、消息、摘要和长期记忆先按版本化策略和保守 token 估算选择，再交给 Qwen 或豆包适配器渲染。适配器仍负责供应商协议格式，不再自行决定业务上下文的优先级。
5. 消息候选只包含当前活动会话，以及同账号、同角色、已完成的普通会话；其他活动通话不得作为上下文。临时会话只读取自身已确认消息，不加载摘要或长期记忆。
6. 候选消息、摘要和记忆都优先保留最新内容；最终消息与摘要按时间正序注入，避免叙事顺序倒置。数据库候选上限继续作为第一道边界，装配器的 token 与渲染字符预算作为第二道边界。
7. 装配结果产生不含正文的诊断元数据：策略版本、供应商、估算指令与上下文 token 数，以及各来源选中和丢弃数量。该元数据可以写入安全日志，用于后续调参和回归分析。

## 后果

- 一次通话在断线恢复、角色编辑和模型停用前后保持稳定的人设、声音与模型选择。
- 家庭成员仍按账号和角色隔离；同一账号对同一角色发起的并发通话也不会互相读取未完成内容。
- Qwen 与豆包共享同一套选择语义，但可以拥有不同预算；预算调整必须升级策略版本并增加回归测试。
- 数据库新增 `conversation_runtime_snapshots` 表，删除会话时级联删除快照。
- 旧的活动会话在首次重连时补建快照；无法生成合法快照时明确拒绝握手，不使用浏览器提交的运行时配置。

## 不包含

- 长通话中的增量摘要检查点；
- 在供应商音频或轮次上限前无感轮换实时连接；
- 精确供应商 tokenizer 或动态成本模型；
- 跨供应商、模型或音色的自动故障切换。

这些能力需要在现有快照和装配器之上另行决策与实施。

## 重新评估条件

- 供应商提供可恢复原会话且能验证配置一致性的稳定会话 ID；
- 长通话频繁触发供应商轮次或音频上限；
- 估算 token 与供应商实际用量长期偏差明显；
- 需要对不同角色类型或账号年龄采用不同上下文策略。
