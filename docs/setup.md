# 本地运行与配置

本文说明首次启动、管理员模型设置、可选能力和升级流程。产品理念与整体架构见 [README](../README.md)，基础配置以 [`.env.example`](../.env.example) 为准。

## 1. 启动应用

环境要求：Node.js 22.12 或更高版本、pnpm 10、可连接的 PostgreSQL。先创建空数据库，再执行：

```bash
cp .env.example .env
pnpm install
```

在 `.env` 中填写 `DATABASE_URL`，然后初始化数据库与首个管理员：

```bash
pnpm db:migrate
pnpm admin:init --username admin --display-name 家庭管理员
pnpm dev
```

`admin:init` 仅能在没有任何账号的数据库中执行。密码在终端中遮罩输入两次，不进入命令历史；不接受空密码，不限制长度或组成。应用没有公开注册入口，其他家庭成员由管理员登录后创建。

`pnpm dev` 同时启动 Web、API 和独立 Worker，Web 与 API 的默认端口分别为 `5173` 和 `8787`。也可以分别使用 `pnpm dev:web`、`pnpm dev:api` 和 `pnpm dev:worker`；会话摘要、记忆提取、索引同步与媒体清理需要 Worker 运行。

| 配置 | 用途 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 业务数据与后台任务共用连接 |
| `API_HOST`、`API_PORT`、`WEB_PORT` | 本地监听地址和端口 |
| `AUTH_COOKIE_SECURE` | 本地 HTTP 开发为 `false`；生产 HTTPS 部署必须为 `true` |
| `AUTH_SESSION_TTL_DAYS` | 登录会话有效期，示例为 30 天 |
| `AUTH_LOGIN_MAX_ATTEMPTS`、`AUTH_LOGIN_WINDOW_SECONDS` | 登录尝试限制，示例为 300 秒内 10 次 |
| `MEDIA_LOCAL_DIR` | 私人媒体目录，示例为 `./data/media` |
| `EMBEDDING_LOCAL_CACHE_DIR` | 内置向量模型的持久化缓存目录 |
| `MEM0_TELEMETRY` | 示例为 `false`，关闭 Mem0 OSS SDK 的匿名遥测 |

生产环境的云平台、域名、HTTPS、磁盘快照和运维由项目所有者管理。`MEDIA_LOCAL_DIR` 应位于持久化磁盘，并与 PostgreSQL 一起纳入快照；媒体只能经带账号认证的 API 读取。应用不提供整站备份或恢复功能。

## 2. 配置模型并开始通话

管理员登录后进入“我的 → 模型设置”，按以下顺序配置：

1. 创建供应商连接，录入服务端端点与凭据。
2. 为连接添加模型；实时模型选择音色，Embedding 模型填写或选择维度。
3. 测试候选配置。管理员点击测试会执行真实请求，外部模型可能计费；测试成功后才能启用模型。
4. 启用模型，并分别设置实时默认和所需用途。

实时模型使用千问或豆包适配器；文本模型支持 Bearer API Key、HTTPS Base URL、标准 `/chat/completions` JSON Mode，可选择标准或阿里百炼兼容预设。连接修改先保存为候选修订，只有测试成功才原子替换活动配置；测试失败保留旧活动配置。

用途需要逐项显式绑定，可以绑定同一个模型配置，但不会隐式复用其他用途：

| 用途 | 配置标识 | 生效范围 |
| --- | --- | --- |
| 实时默认 | `realtime_default` | 新角色的预选模型；不会改动已有角色 |
| 会话摘要 | `conversation_summary` | 增量摘要检查点和结束后的最终摘要 |
| 长期记忆提取 | `memory_extraction` | 普通通话结束后的分级事实提取 |
| 长期记忆向量化 | `memory_embedding` | 可选的 Mem0 语义索引 |
| 教学计划生成 | `teaching_plan_generation` | 成人配置阶段生成待确认短期计划 |

没有摘要或记忆用途绑定时，会话照常保存，相关工作进入“等待模型配置”；补齐绑定后自动补发。API 和 Worker 动态读取活动配置，无需重启。临时对话仍保存本次文字历史与摘要，但不加载以前的私人关系，也不提取长期记忆。

API 密钥按 [ADR-0029](decisions/0029-admin-managed-model-configuration.md) 明文保存在私有 PostgreSQL 中，浏览器和管理 API 只能看到“已配置”，不会获得密钥内容；日志、审计和错误响应也不得回显密钥。数据库和磁盘快照需要按包含供应商凭据的标准保护。

星盾队长、林老师和知夏三个预置角色初始化后即可在首页查看；完成模型配置并确认角色绑定后可以通话。管理员可以编辑角色绑定的已启用模型和音色；角色创建与编辑页也可用固定短句试听，试听不创建业务通话、不申请麦克风。共享角色全家使用同一声音。

从角色卡的“通话”按钮进入后，可以检查角色开场、连续免提聊天、用户与角色字幕、语义打断、手动停止和按住说话。当前产品链路使用 WebSocket PCM 中继；千问的按住说话只控制本地音频发送，松开后仍由 `smart_turn` 判断轮次。WebRTC 保留为实验与诊断路径，详见 [千问 WebRTC 技术验证](spikes/qwen-realtime-webrtc.md)。

## 3. 管理家庭账号

管理员在“我的 → 家庭成员”创建成人或儿童账号、重置成员密码，并为每个儿童账号配置是否允许管理员查看其历史、记忆和已保留录音。这个开关不授予管理员读取成人私人内容的权限。

所有成员都可以在“我的”验证当前密码后修改自己的密码；成功后撤销其他设备的有效登录会话，当前设备保持登录。每台设备只保持一个账号，切换成员需先退出。

管理员忘记密码时，在服务器终端执行：

```bash
pnpm admin:reset-password --username admin
```

重置成功后，该管理员的全部现有登录会话都会撤销。应用不接入邮箱找回；账号停用与恢复的产品流程仍待确认。

## 4. 可选：启用 Mem0 语义记忆

Mem0 OSS 直接运行在 API 和 Worker 进程中，向量表使用同一个 PostgreSQL；无需 Mem0 云端账号或独立 Mem0 服务。不启用语义索引时，普通业务迁移不要求安装 pgvector。

启用步骤：

1. 在 PostgreSQL 服务器安装与数据库版本兼容的 pgvector 扩展文件。数据库账号需具备创建扩展和表的相应权限；首次使用会执行 `CREATE EXTENSION IF NOT EXISTS vector` 并创建 collection 表。
2. 在“我的 → 模型设置”创建 Embedding 连接，选择内置本地模式或 OpenAI-compatible `/embeddings` 外部服务。
3. 测试模型并核对返回维度，启用后绑定“长期记忆向量化”用途。API 和 Worker 无需重启。
4. 在“记忆 → Mem0 诊断”查看业务记忆、同步映射和实际索引记录，按角色测试语义召回。

内置模式使用 `fastembed@2.1.0` 支持的 7 个稠密模型，中文默认推荐 `fast-bge-small-zh-v1.5`（512 维，约 90 MB）。首次测试会下载 ONNX 模型到 `EMBEDDING_LOCAL_CACHE_DIR`；之后记忆正文和查询在本地进程内向量化。API 与 Worker 共用磁盘缓存，但各自加载一份推理实例。选择外部云端 Embedding 时，已确认记忆和召回查询会发送到该服务。

PostgreSQL 的 `character_memories` 始终是权威来源，只有已确认的 `active` 记忆进入索引。召回结果先作为本地 ID 回查账号、角色与状态，再参与上下文；搜索超时或不可用时回退到最近记忆。临时对话不搜索或写入索引。配置变化会派生新 collection 并补发重建任务，旧 collection 由运维确认迁移完成后清理。完整边界见 [ADR-0032](decisions/0032-mem0-semantic-memory-index.md)。

## 5. 可选：启用学习小支线

学习小支线由成人配置、儿童使用，默认关闭。所有未删除的预置角色与家庭公共角色都可以保存计划，成人私有角色需先共享；计划“可生效”与“待生效”由实时配置是否满足能力门禁决定。

### 配置精确允许列表

先执行普通数据库迁移。部署者完成对应配置的受控验证与审阅后，才在 `.env` 开启 `TEACHING_QWEN_DYNAMIC_ENABLED=true`，并填写首条完整绑定：

| 变量 | 必须填写的内容 |
| --- | --- |
| `TEACHING_QWEN_MODEL_PROFILE_ID` | 本次审阅的模型配置 ID |
| `TEACHING_QWEN_MODEL_PROFILE_REVISION` | 对应模型配置修订号 |
| `TEACHING_QWEN_CONNECTION_ID` | 对应供应商连接 ID |
| `TEACHING_QWEN_CONNECTION_REVISION` | 对应连接修订号 |

额外绑定使用 `TEACHING_QWEN_DYNAMIC_ADDITIONAL_BINDINGS`，值为严格 JSON 数组，每项同时包含 `modelProfileId`、`modelProfileRevision`、`connectionId`、`connectionRevision`。ID 使用实际配置 UUID，修订号使用对应整数；不要只填模型名称，也不要混用不同已审阅绑定的字段。修改这些启动环境配置后，需要重启 API。

当前动态教学协议支持集合仅为 `qwen-audio-3.0-realtime-plus` 和 `qwen-audio-3.0-realtime-flash`。每个模型配置与连接修订必须逐条批准；批准 Plus 不会解锁 Flash，反之亦然。任一修订改变后，该绑定不再具有执行资格，需要重新审阅。豆包、其他模型和未批准连接可以保存待生效计划，但不会执行动态支线，也不会静默改用其他模型或声音。

### 生成、确认和体验

1. 管理员先创建、测试并启用文本模型，单独绑定“教学计划生成模型（短期计划必需）”。缺少该用途时不能生成，也不会使用本地模板或其他用途模型回退。
2. 管理员或成人进入“我的 → 学习小支线”，选择儿童、家庭公共角色、年级、主题、难度与出现方式；填写最多 300 字的具体目标，选择 3～8 个活动及 7 天或 14 天有效期。只填写学习内容，不填写个人资料。
3. 点击“生成短期计划”。每次新生成可能产生一次模型费用；网络结果未知或已有成功草稿时，同一计划修订只查询原任务，刷新、重复点击或换请求 ID 都不会新增收费任务。确需再次调用模型时，先修改并保存设置形成新的计划修订。
4. 逐项核对题目、选项、参考答案、讲解与反馈，再“确认并启用”。预览固定标注“模型生成 · 未联网”；当前没有网页、文件或知识库检索，结构校验不能保证事实正确。草稿未确认或生成失败不会覆盖已启用内容。
5. 切换至对应儿童账号，从可生效角色进入普通通话。麦克风和 Provider 连接开始前，儿童会看到 AI 身份、成人配置目标和不评分的透明说明，可以选择“本次只聊天”。
6. 儿童可以点击“现在来一个”主动开始活动；“合适时轻轻邀请”还需满足通话至少 5 分钟、至少 6 个有效儿童轮次和 24 小时冷却，才在安全回复边界尝试一次。

每次通话最多一个活动、最多两次角色回复，完成后恢复普通角色指令。明确拒绝或安全优先内容出现后，本次通话不再邀请；临时对话始终只聊天。系统只记录粗粒度状态，不生成分数、等级、掌握结论或能力画像。成人配置计划也不会额外获得儿童会话、记忆或逐次回答的读取权限。

配置阶段模型只读取成人主动填写的计划字段，不读取儿童历史、记忆、家庭资料或角色完整 Prompt。模型候选经 strict DTO 校验和固定编译器处理，不能覆盖版本、学科等服务端权威字段，也不能提供系统 Prompt、工具调用或放宽拒绝与回复上限规则。完整设计见 [ADR-0033](decisions/0033-low-disruption-role-learning-branches.md) 和 [ADR-0035](decisions/0035-generated-short-term-learning-plans.md)。

### 真实 Provider Spike 的授权边界

产品教学开关与协议 Spike 是独立流程。专用 Spike 默认只生成 preflight；真实调用必须有一次性持久化授权、固定价格快照与人民币预算，并在本地交互式终端对完整 `planHash` 二次确认。普通开发、自动测试或开启产品开关不构成真实 Spike 调用授权。

默认使用 `TEACHING_SPIKE_DATABASE_URL` 指向的独立可丢弃数据库。逐次显式添加 `--use-application-database` 才使用现有应用数据库，且 preflight 与 execute 都需提供；该模式只读取精确模型配置及数据库时钟，唯一允许写入的是专用授权表，不能读取家庭私人内容。CLI 不自动执行迁移。详细操作见 [实时动态教学指令能力验证](spikes/realtime-dynamic-teaching-directives.md) 和 [ADR-0034](decisions/0034-existing-database-live-spike-validation.md)。

已有隔离文本小样本只提供协议执行证据，仍是 `insufficient_sample`；不能视为儿童学习效果、长通话稳定性、真实语音设备或其他 Provider 已完成验收。

## 6. 迁移我和某个角色的关系数据

适用于测试账号转正式账号或更换私有部署：

1. 使用来源账号登录，在角色详情选择“迁移我和这个角色的数据”，导出 JSON 文件。
2. 退出并登录目标账号，打开对应角色，再导入文件；角色不匹配时需要再次确认目标。
3. 查看导入结果，发起一次新的普通通话继续关系。原服务中尚在进行的通话只作为已完成历史导入，不恢复旧实时连接。

文件包含当前账号与该角色的文字历史、摘要和全部状态的长期记忆，不含账号、密码、模型密钥、角色定义、家庭资料、学习计划、图片或录音。导入重新生成目标账号下的本地 ID；同一文件重复导入返回原结果，重复记忆不会覆盖目标账号已有的审阅决定，也不会重新生成摘要或记忆提取任务。

迁移文件是带版本与 SHA-256 完整性校验的未加密 JSON，最大 25 MB。校验不提供加密或来源身份认证，文件应放在可信位置或使用后删除。这是私人关系迁移，不能替代角色卡包或整站备份。完整规则见 [ADR-0036](decisions/0036-account-character-relationship-data-transfer.md)。

## 7. 升级现有部署

升级前由项目所有者按现有运维方式为数据库和媒体做快照。更新依赖后执行 `pnpm db:migrate`，检查 `.env.example` 的基础配置变化，再启动 API、Web 和 Worker；不要重新执行只适用于空库的 `admin:init`。

从旧环境变量模型配置升级到管理员模型设置时，迁移会保留角色、模型与音色 ID，但将原模型置为未配置草稿。管理员以相同供应商和模型 ID 创建配置会重新挂接原记录；完成测试、启用、实时默认与摘要/记忆用途绑定后，原角色恢复通话，等待分析的会话自动补发。

遗留的 `DASHSCOPE_API_KEY`、`QWEN_*`、`DOUBAO_*`、`QWEN_ANALYSIS_*`、`MEM0_ENABLED` 和 `MEM0_EMBEDDING_*` 模型配置不会被导入或继续读取。实时、文本和 Embedding 的连接、密钥与用途均由管理员在产品内维护；教学允许列表与数据库、认证、媒体等基础配置继续使用 `.env`。

更改教学相关模型或连接修订后，需要重新核对允许列表。更改 Embedding 模式、端点、模型或维度后，需要观察新 collection 的重建状态，再决定何时清理旧索引。PWA 检测到新版本会提示刷新，活跃通话中不会自动重载。
