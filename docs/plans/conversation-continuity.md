# 通话收尾与再次进入：产品方案

状态：Accepted，已按 [ADR-0038](../decisions/0038-conversation-continuity.md) 实施 A、B、C 三个阶段；实机验收边界见文末。\
日期：2026-09-08\
目标：结束有确认，回来能接上。

## 1. 用户能得到什么

- 挂断立即停止声音和麦克风，随后明确知道文字是否已保存。
- 不必等待摘要和长期记忆整理，就能离开页面。
- 再次打开应用，能找到刚才中断的通话，并主动恢复。
- 正常结束后，下次聊天承接既有关系；结束后的通话记录保持完整、独立。
- 不再要求用户理解“会话状态、检查点、摘要任务”等内部概念。

## 2. 四个操作的含义

| 当前情况 | 入口文案 | 结果 |
| --- | --- | --- |
| 普通通话中断，当前没有设备占用 | 恢复通话 | 恢复原业务会话、模式、人设快照、模型和声音；使用已保存内容 |
| 普通通话已完成 | 再次聊天 | 新建普通会话，加载该账号与角色的既有关系；采用当前角色配置 |
| 临时通话中断 | 恢复临时对话 | 恢复原临时会话，只使用本次已保存内容 |
| 临时通话已完成 | 新的临时对话 | 新建临时会话，不加载旧关系或这次已结束的临时内容 |

“恢复通话”不重播旧语音，不重复首次开场。恢复就绪时显示“已接上，可以继续说”；模型不凭空补写未听清、未保存的最后一句。用户先开口，避免中断处重复发言。

第一版不增加“从任意一条历史精确分支继续”的能力。“再次聊天”延续整体关系，不声称必然从被查看历史的最后一句开始。

## 3. 挂断后的收尾页

### 3.1 正常结束

点击“结束”后先停止采集和播放，再同步剩余已完成文字并确认结束记录。页面切为轻量收尾卡，不重新出现一个没有解释的“开始通话”按钮。

示例：

> 和知夏的通话已结束\
> 今天 20:42 · 通话 18 分钟\
> ✓ 文字记录已保存\
> 本次回顾：整理中\
> 长期记忆：整理中，可以稍后查看\
> **返回角色**　查看记录

“文字已保存”必须来自服务端确认，不能依据声音已停止或本地队列为空推断。若文字都已确认但结束请求结果未知，显示“文字已保存，正在确认结束状态”，查询原操作结果，不重复创建通话。

收尾页不自动倒计时跳走，不要求评价，不把记忆审阅变成退出前必做事项。用户可以在文字保存与结束确认完成后立即返回角色；摘要和记忆继续异步处理。

### 3.2 后台整理状态

| 状态 | 本次回顾 | 长期记忆 |
| --- | --- | --- |
| 正在处理 | 正在整理，可以稍后查看 | 正在整理，可以稍后查看 |
| 已完成 | 显示简短回顾，可展开完整内容 | 新保存 X 条、待确认 Y 条；可查看本次记忆 |
| 完成但无新记忆 | — | 本次没有新增需要长期记住的内容 |
| 尚未配置 | 暂未启用回顾整理，文字已保存 | 暂未启用长期记忆整理，文字已保存 |
| 处理失败 | 回顾暂未整理完成，文字已保存 | 记忆暂未整理完成，文字已保存 |
| 临时通话 | 仅在本次历史中提供回顾 | 临时对话不新增长期记忆 |

状态、回顾和记忆计数来自真实处理结果。不以“我都记住了”代替这些状态，也不为生成收尾卡额外调用实时模型。整理失败沿用现有任务恢复机制；首版不建设新的队列管理界面。

时长使用有效连接期间累计的通话时间，不把关闭应用后的间隔或数小时待处理时间算入；历史同时保留开始时间和最后活动时间。

### 3.3 保存失败

示例：

> 通话已停止，还有 2 条文字未同步\
> 已保存至 20:41:36。请保持此页面打开，网络恢复后可以重试。\
> **重试保存**　查看已保存记录

保存未完成时，应用内返回、切换页面和退出登录都先进入同一个待同步处理流程，不直接卸载持有待发送文字的通话页面。查看已保存记录时也保留待同步状态。

用户坚持离开时，明确说明未同步条数，并提供“留在此页”和“放弃未同步文字并离开”；该操作不删除服务端已经保存的内容。离开不等于成功结束，首页仍保留待处理记录，直到完成服务端收尾。

首版不声称可以阻止系统强杀、浏览器回收或强制刷新。对这些情况只能恢复服务端已确认的文字；最后未同步部分可能丢失。需要在有待同步内容时清楚提示，而不是正常通话期间持续警告。

## 4. 首页如何接回用户

首页顺序调整为：需要处理的通话 → 最近聊过 → 收藏 → 全部角色。各区块为空时不占位，不改变角色卡独立通话按钮的约定。

### 4.1 需要处理的通话

- 只展示当前账号本人的记录，不能根据数据库 `active` 单独判断异常。
- 服务端确认原连接已失效后，才提供“恢复通话／结束并保存”；连接存活情况还不明确时显示“正在确认通话状态”。
- 另一台设备仍在同一通话中，显示“正在另一台设备通话”，首版不提供强制接管或远程结束。
- 卡片展示角色、普通或临时模式、最后活动时间、最后已保存时间；不直接显示私人话题正文。
- 默认展开最近一项，其余用“还有 N 次待处理”进入完整列表；不能静默丢弃旧记录。
- 用户可以先找另一个角色聊天，待处理项不形成应用级阻塞，也不引入全局并发通话上限。

“结束并保存”只收尾已有内容，不连接语音模型、不打开麦克风。若当前设备还有已知未同步文字，必须先补写或由用户明确放弃；其他设备可能残留的未上传内容不能承诺已经保存。

### 4.2 最近聊过与收藏

- 最近聊过默认展示 4 个不同角色，按本人最近一次已完成普通通话的有效活动时间排序；每个角色只出现一次。
- 展示头像、角色名和“上次聊天：今天 20:42”，按钮为“再次聊天”；点击其他区域进入角色详情。
- 已完成临时通话仍可在历史中查看，但不进入跨会话的最近话题或关系卡。
- 收藏按账号保存，可从角色卡和详情切换；不改变角色共享范围或声音。收藏状态在卡片上可辨识，收藏与最近区块允许引用同一角色。
- 没有普通通话时直接展示收藏和全部角色，不出现空的“最近聊过”。

## 5. 角色详情与历史

角色详情的主顺序：角色简介和通话 → 我和角色的聊天 → 最近普通通话 → 更多角色设置。

“我和角色的聊天”首版展示最近一次已完成普通通话的短回顾，以及已保存记忆与待确认记忆入口，不宣称是一份完整人格或关系画像。长篇设定、复制、恢复预置和迁移收进“更多”。

回顾只在本人主动打开详情或历史后显示。摘要尚未完成时提供时间、记录数和“查看文字记录”；不把最后一句敏感转写直接填到首页，也不重新调用模型补一个首页标题。

历史卡片区分“已结束”“已中断，可恢复”“正在通话”“等待结束确认”。选中已结束普通记录的按钮是“再次聊天”；选中已中断记录才是“恢复通话”。临时记录采用第 2 节的独立语义。

管理员按已有权限查看儿童历史时保持只读，不能替儿童恢复、结束、发言或管理私人记忆。管理员自己的首页不汇总儿童待处理通话。

## 6. 中断恢复规则

| 场景 | 产品行为 |
| --- | --- |
| 原页面仍在，短暂断网或前后台切换 | 沿用已有约 30 秒自动恢复；成功后继续原通话 |
| 页面刷新、PWA 被回收、重新登录后回到应用 | 检查本人未完成通话并显示入口，点击后才申请麦克风与建立连接 |
| 恢复时仍有同会话在线设备 | 提示去原设备继续；不抢占，不合并两边内容 |
| 恢复失败 | 同模型重试或结束保存，不静默换模型、音色或角色 |
| 原角色已删除、权限撤回或原配置无法使用 | 解释无法恢复原因，按现有历史读取权限保留查看与本人收尾入口；不重建角色或换另一个角色接话 |
| 再次点击恢复、结束请求超时、两个页面同时操作 | 返回同一权威结果，不重复创建记录、消息、摘要或记忆任务 |
| 恢复过程中另一个请求已完成该通话 | 返回已结束状态；如要继续，由用户“再次聊天”创建新通话 |
| 学习支线曾拒绝或中断 | 原会话的只聊天、次数和冷却继续有效；不重放题目、不重新邀请，不把刷新视为新机会 |
| 中断很久才回来 | 不自动删除或因时间长重启成新会话，展示实际日期；恢复能力仍按当前权限、快照与服务可用性校验 |

首版不要求跨设备迁移仍在播放的音频，也不恢复未完成的语音草稿。新设备只能获得服务端已保存部分；不会扫描其他设备私人缓存。

## 7. 为实现体验需要补的基础能力

这部分不作为页面文案。

1. 会话记录继续保持活动/完成生命周期，同时新增服务端连接存活状态、最后有效活动时间、累计通话时长和结束请求状态。用户可见的中断、等待确认等状态由权威信息组合，不能用浏览器内存或消息更新时间代替在线检测。
2. 同一业务会话在任意时刻仅一个客户端持有写入与恢复资格。通过有期限的连接占用记录和连接代次，阻止旧页面迟到的消息、恢复或结束请求改变新连接。约束只针对同一会话，不限制账号或全局的独立通话数量。具体续租和失联判断阈值在技术方案与测试中确定。
3. 恢复、结束使用稳定请求标识和可查询结果。结束请求固定客户端最后一条已完成文字的序号；服务端验证文字齐全后才完成会话。响应丢失时查原结果，消息采用已有稳定 ID 与连续序号补写。本机可保存不含正文的待结束操作标记（部署、账号、会话、请求标识、目标序号）；同账号重新认证后先核对收尾结果，不把已经点击结束的会话直接引导为恢复。完成或删除后清理该标记，不保存密钥和角色内容。
4. 新增本人通话状态查询、待处理列表、恢复准备接口；现有列表和详情补充最终回顾、后台处理状态与按来源会话统计的记忆信息。
5. 冷启动恢复沿用已有运行时快照与上下文装配，但服务端还要保存开场是否已发生及教学状态；已恢复连接不得使用重新加载页面后的默认开场标志。
6. 正常结束时间取最后真实通话活动，不能用几天后点击“结束并保存”的时间冒充通话时长；收尾确认时间另存。恢复形成多个连接段时，时长按段累计。
7. 记忆计数按来源和当前可见状态展示，恢复、重复完成、Worker 重试都不得造成重复条目；索引同步不阻塞文字保存或退出。

已有约束依据：ADR-0006、0010、0017、0021、0022、0030、0031、0033、0036、0037。实施决策由 ADR-0038 补充；连接采用 10 秒心跳与 45 秒失联租期，写入资格和连接存活分别校验。

## 8. 本机待同步文字：单独取舍

**本方案首版推荐只保证恢复服务端已确认的内容。** 已打开页面内继续保留和重试尚未同步的文字，完成前不直接卸载。只在本机保留必要的待结束操作标记，不持久保存私人文字正文；Service Worker 不缓存私人响应、音频、角色 Prompt 或凭据。若原目标序号表明有缺失，而原页面文字已丢失，提示可确认结束并仅保留已收到内容，不声称完整恢复。

如果进一步要求“断网后被系统杀掉，也尽量保住最后几句”，需要一个独立的本机短期待同步队列方案。它会新增私人数据存储位置，需要明确账号重新认证、退出/切换账号清理、保存期限、容量上限、过期提醒和确认后清除规则；不能只加一份无限期缓存。本次不默认引入该能力，也不把它当作已获得的产品保证。

## 9. 实施顺序

| 阶段 | 完成交付 | 验收重点 |
| --- | --- | --- |
| A：结束有确认 | 挂断收尾、真实保存状态、失败重试、结果未知查询、后台整理状态 | 声音立即停止；保存失败不直接退出；完成操作可重复查询 |
| B：中断能恢复 | 服务端在线占用、跨页面恢复、首页待处理与历史恢复入口 | 同一次通话恢复；不会重开场、抢占、串入其他会话或重启教学 |
| C：再次回来容易 | 最近角色、个人收藏、详情回顾、记忆入口、历史状态统一 | 常聊角色易找到；正常与临时模式语义一致；不依赖回顾已完成 |

A、B 是“可靠闭环”的交付门槛；C 完成本项需求的日常回访体验。暂不扩展录音、拍题、AI 角色生成、任意历史分支、主动提醒或全站备份。

## 10. 验收场景

1. 正常聊完点击结束：麦克风和声音先停止；服务端确认前不显示文字已保存；不等后台模型即可离开。
2. 最后两条文字上传失败：显示准确待同步数量和最后已保存位置；点击返回不会静默丢失队列。
3. 结束请求已到服务端但响应丢失：查询后显示已结束；只有一份会话、一组后台任务。
4. 关闭页面后重开：本人首页可发现中断通话；不自动开麦；点击后从同一会话的已保存上下文恢复，无重复开场。
5. 同一账号两台设备：不能同时恢复同一会话；旧设备迟到消息和结束操作不能覆盖新状态；独立的其他会话不被影响。
6. 临时通话中断可恢复本次；临时通话结束后再开不带入以前关系或已结束临时内容，不提取长期记忆。
7. 儿童之前选了只聊天或拒绝过：刷新恢复后仍保持；中断的小挑战不重复。
8. 摘要/记忆未配置、失败或尚未完成：文字记录、离开页面、再次聊天保持可用，状态不伪装成功。
9. 同一角色多次普通聊天：最近区只占一个位置；详情只展示本人可读内容；首页不显示私人话题正文。
10. 角色权限变化、账号失效或记录删除：恢复重新校验；已删除内容不因待处理入口或重复请求复活。
11. 首次建连失败、尚无有效消息：不给用户制造一张长期待处理的空通话卡；无其他设备占用时幂等收尾，保留必要失败信息。
12. 真机分别覆盖正常挂断、浏览器返回、刷新、PWA 回收、锁屏、断网与重新登录。自动化证明状态与幂等，真机确认自然度和设备行为，二者不混为同一结论。

## 11. 实施与验证记录

- A：独立收尾页、同步失败保留内存队列、同账号重新认证、查看历史覆盖层、固定目标序号及原结束请求查询。
- B：服务端写入代次、单连接占用、浏览器 Pong 续租、恢复准备、原模式和快照恢复、旧连接隔离、空失败会话收口。
- C：本人待处理入口、最近不同角色、私人收藏、详情回顾与来源记忆、普通/临时及监护只读历史动作。
- 数据库变更：`0024_conversation_continuity.sql`；完整迁移已在本机隔离 PostgreSQL 验证。2026-09-08 按用户授权，在当前项目配置的本机数据库应用了待执行的 `0023`、`0024`，已核对迁移哈希、新表约束和既有通话控制状态回填，无剩余待执行迁移。
- 最终门禁：带隔离数据库配置的 `pnpm check` 通过，包含格式、ESLint、全仓类型检查、1006 项测试和完整构建。15 项真实数据库/HTTP 集成场景包含在该测试总数内。
- 生产前端构建的 Chromium 烟测通过首页隐私、390px 布局、详情回顾、同会话恢复、无重复开场、写入标识握手、失败尾部保留、历史覆盖层、补写去重、结束响应丢失查询和已完成待处理卡消失。
- 模型与音频采用模拟服务和浏览器虚拟麦克风。真实手机/PWA 系统回收、外放与供应商自然度尚未实机验收；未同步文字仍仅能在原页面内存存续时重试。
